# v1.3 — Event Clustering implementation note

> This is a non-authoritative implementation note. The frozen Architecture,
> Data, and Runtime / Failure Contracts remain canonical.
>
> Status: COMPLETED / CLOSED after real-model acceptance under corrected 24h
> Morning Brief story-bundle semantics (2026-08-27).

## Scope

The side-by-side stage accepts canonical `Article[]` and returns only
`EventCandidate[]`. It owns event membership and deterministic candidate
identity. It does not select, rank, classify, write, translate, render, or
route production output.

Generation 1 remains on its existing `.venv` and production routing. This
stage is not imported by `main.py`, the launch scripts, the RSS collector, the
DeepSeek path, Bark, or Obsidian.

## Operational Event semantics

For v1.x, an Event / EventCandidate is a reader-level story bundle inside one
approximately 24-hour Morning Brief report window. It is not a persistent or
historical identity for one strictly atomic real-world occurrence.

Announcement, immediate reaction, clarification, closely related follow-up,
and complementary perspectives may belong to one bundle when presenting them
as separate Morning Brief items would be materially repetitive and a writer
can naturally synthesize them. Shared keywords, country, company, or topic are
not sufficient: gun buyback versus share buyback or reverse repo, unrelated
sanctions actions, same-country unrelated developments, and different material
company events must remain separate when readers would treat them as distinct
news stories.

The normal input is canonical Articles from the current report window, not a
multi-day knowledge graph, historical story tracker, cross-week database, or
persistent event identity service. v1.5 Event Writer will read the complete
Article provenance of a bundle and synthesize material facts and perspectives
in `title_zh`, `summary_zh`, and `why_it_matters_zh`; clustering does not write
or discard those perspectives.

v1.3 remains local embedding + semantic similarity + simple deterministic
clustering. It must not use DeepSeek, a local LLM pair verifier, LLM
adjudication, translation, or second-pass AI clustering.

## Projection and algorithm

`event_cluster.py` exposes the injectable `EmbeddingBackend` boundary and the
versioned projection:

```text
query: {article.title}
{first 300 Unicode characters of article.summary}
```

The second line is omitted for null or empty summaries. The version is
`article-title-summary-v1`; no source, URL, language, category, importance,
translation, or full content is included.

For two or more valid Articles, the stage sorts by `article_id`, obtains one
embedding per Article, L2-normalizes the vectors, computes pairwise cosine
similarity, adds edges at the supplied threshold, and computes deterministic
connected components with union-find. Singleton components are retained and
all `EventCandidate` objects are constructed through
`EventCandidate.from_article_ids`, then sorted by `event_candidate_id`.

A single valid Article becomes a singleton without initializing the model.
Empty input is a successful empty result. Item validation, embedding, model
initialization, and global similarity/component failures follow the frozen
`StageResult` semantics; no retry, LLM fallback, or Generation 1 semantic
fallback is used.

Diagnostics are optional and non-canonical. They contain bounded edge samples,
safe model/runtime metadata, counts, projection and algorithm versions, and
timings. They do not contain embeddings, full matrices, article text, raw
exceptions, credentials, or secrets.

## Fixtures and validation paths

`tests/fixtures/event_clustering_v1_3.json` contains seven labeled cases, 19
fixture Articles, 17 labeled article pairs, and 14 expected clusters. Each case
declares its acceptance class (`production-relevant`, `robustness-only`, or
`outside-normal-window`), window relevance, and explicit provenance note. The
four production-relevant cases are reconstructed from documented production
incidents; exact source provenance is not available in the tracked repository.
The Treasury and connected-components cases are synthetic robustness fixtures.
The fixture intentionally remains small and is not presented as a production
benchmark.

`tests/offline_event_cluster_smoke.py` injects deterministic fake embeddings
and covers empty/singleton behavior, multilingual and same-event examples,
same-keyword negatives, chaining risk, order/repeat determinism, canonical
fields, diagnostics, and all specified failure paths. It never imports or
downloads Sentence Transformers.

`scripts/evaluate_event_clustering.py` is a separately invoked real-model
path. It loads the frozen local model revision once, reports similarity
distribution and initialization/embedding timings, sweeps a threshold range,
reports expected versus actual story-bundle memberships, computes
production-critical overmerge/split and production precision/recall/F0.5,
separates synthetic robustness failures from outside-window observations, and
checks deterministic repeat at the accepted threshold. It is not part of
offline regression.

Acceptance concepts are classified without changing fixture facts or labels:

- **A — production-relevant Morning Brief acceptance:** announcement / reaction /
  follow-up; gun / share / reverse-repo negatives; same-window broad-topic
  distinct events.
- **B — useful synthetic robustness:** Treasury cross-language and the chaining
  fixture (`A≈B`, `B≈C`, `A≠C`). Chaining remains measured explicitly.
- **C — invalid / overly strict event-identity assumption:** a temporal Iran
  sanctions early/later pair that would not normally coexist under actual
  ingest/window semantics is not a production critical hard-negative gate.

The first implementation keeps the approved connected-components algorithm;
no centroid or agglomerative rule is introduced without representative
evidence. The acceptance question is whether readers should consume the
Articles as one story in the same report window, not whether they are one
strictly atomic occurrence.

## Accepted model, dependency, and threshold

The accepted target is `intfloat/multilingual-e5-small` at immutable revision
`614241f622f53c4eeff9890bdc4f31cfecc418b3` (384 dimensions; CPU/float32). The
projection is `article-title-summary-v1` with a 300-Unicode-character summary
cap. The accepted threshold is `0.91`; the observed production-clean interval
was `0.903–0.934`. The algorithm remains `connected-components-v1` with
similarity edges at `similarity >= 0.91`, deterministic union-find, singleton
retention, and `EventCandidate.from_article_ids()`.

The Python 3.9-compatible direct dependency pins are:

```text
sentence-transformers==3.4.1
transformers==4.48.1
torch==2.5.1
```

The initial read-only CPython 3.9 / macOS arm64 resolution failure remains
historical evidence. The current project `.venv` imports these pins and
`pip check` reports no broken requirements. The accepted evaluator completed
with 19 Articles, CPU inference, 384-dimensional vectors, and deterministic
repeat at threshold `0.91` without changing Generation 1 production.

Explicit real-model runs should use a writable local cache. By default the
evaluator resolves `AUTOMATION_BRIEF_MODEL_CACHE` when set, otherwise
`<canonical data root>/runs/model-cache`; `--cache-folder` remains an explicit
override. This is evaluator/runtime setup only: model binaries and cache are
never committed, and v1.3 does not alter Generation 1 runtime behavior.

The accepted production gate is reader-level story-bundle membership in the
same report window. At `0.91`, production-critical overmerge and split are both
zero, production precision/recall/F0.5 are all `1.0`, and expected production
memberships are exact `8/8`. Treasury cross-language remains a synthetic split
and the temporal Iran pair remains an outside-window observation; neither
invalidates the closeout.
